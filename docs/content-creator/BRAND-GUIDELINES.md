# Brand Guidelines

## Current Positioning

Arya Teja Rudraraju is a founder and agentic systems builder helping teams design, secure, and ship practical AI agent systems and local-first workflows.

Public focus:

- Direct consulting through AryaTeja.com for secure AI agent setup, workflow audits, local-first systems, remote agent access, automation, and practical implementation.
- Building lesearch.ai, described in current public copy as an AI-agent OS and research workspace.
- Building LeCoder MConnect, an open-source mobile bridge for coding agents and remote terminal workflows.
- Writing about agent memory, multi-agent coordination, open-source agents, context engineering, and business-first AI adoption.

## Voice

Sound like:

- A builder learning and shipping in public.
- Technical, but business-first.
- Grounded, capable, and generous.
- Direct about tradeoffs and uncertainty.
- Helpful to founders and builders who need practical next steps.

Avoid:

- Hype without proof.
- Corporate filler.
- AI PM framing.
- Job-seeker framing.
- "Best", "first", "only", "most secure", or performance claims without direct evidence.
- Over-polished thought-leader voice.
- Em dashes.

## Proof Boundaries

Allowed when sourced:

- Published AryaTeja.com pages.
- Public repo READMEs, source files, releases, issues, and package metadata.
- Screenshots or demos Arya approves for public use.
- Official docs for tools, SDKs, protocols, and platforms.
- Arya's explicit review comments.

Requires `TODO:` or Arya review:

- Customer outcomes.
- Revenue, growth, or adoption numbers.
- Benchmarks.
- Security guarantees.
- Production-readiness claims.
- Private client details.
- Project status not shown in public repo or current site copy.

## Visual Rules

Use:

- Real screenshots, terminal snippets, repo views, architecture diagrams, workflow diagrams, and approved photos.
- Clean, high-contrast layouts.
- Dark or neutral technical palettes that match the portfolio's current AI agent systems and consulting positioning.
- One claim per slide for carousels.
- Clear alt text for every public image.

Avoid:

- Generic robot art.
- Neon hacker cliches.
- Stock-looking AI imagery.
- Fake dashboards.
- Fake customer logos.
- Screenshots with secrets, tokens, private repo names, private email, active tunnels, QR codes, or client data.

## CTA Patterns

Use one CTA per post:

- "If your team is evaluating agent workflows, send the workflow and the constraint. I can help you pressure-test it."
- "If you are building local-first agent systems, follow along. I am sharing the real tradeoffs."
- "Founders: describe the business problem, current workflow, data constraints, and desired outcome."
- "Builders: what would you verify before letting an agent touch this?"

Avoid:

- "Book now" pressure.
- Broad "DM me for AI" pitches.
- Claims that imply guaranteed outcomes.
