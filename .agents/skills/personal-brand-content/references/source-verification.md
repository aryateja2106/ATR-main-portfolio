# Source Verification

Use this whenever a post includes current facts, external repos, security claims, product capabilities, pricing, release status, or tool setup.

## Primary source priority

1. Official docs.
2. GitHub README, source files, releases, issues, or package metadata.
3. Vendor changelog or blog.
4. Standards or security advisories.
5. Secondary commentary only after primary facts are clear.

## What to capture

- Source URL.
- Date accessed if the fact may change.
- Exact version, release, commit, or package name when available.
- What is confirmed.
- What is inference.
- What is still unknown.

## Claims to avoid without proof

- "Best", "first", "only", or "most secure".
- Performance numbers.
- Security guarantees.
- Legal or compliance conclusions.
- "Production-ready" unless the source says so and the evidence supports it.

## Repo breakdown minimum

For open-source project posts, capture:

- What the project does.
- Install path.
- Runtime dependencies.
- License.
- What is reusable.
- What is risky.
- One practical takeaway for builders.
